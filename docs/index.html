The job

AeroVelo Logistics Global has a small pile of approved documents: policies, a supplier procedure, an incident SOP, a bill of materials, a governance matrix, and so on. People currently open those files one by one. The assignment is a notebook that lets someone ask a question and get an answer taken from those files, with the file names that supported it.

That pattern is retrieval-augmented generation, RAG. A search step finds the passages that might contain the answer. A language model then writes the answer from those passages, rather than from whatever it memorised in training. If the files do not contain the fact, the assistant is supposed to say so.

10 files→ clean text→ chunks→ MiniLM vectors→ Chroma→ 4 chunks→ Llama 3.2→ answer + sources

The notebook is worth 100 marks. Setup and imports are not graded. The graded work is the table above.

Rules we do not get to invent

Later cells will be marked against these values. Changing them makes the notebook disagree with the brief.

PieceRequired value
CorpusEvery .md and .pdf under AeroVelo Logistics Global/
MetadataFile name, category (the folder), file type, source path
CleaningCollapse extra whitespace. Leave the words alone.
Chunks800 characters, overlap 120, metadata copied onto each chunk
Embeddingssentence-transformers/all-MiniLM-L6-v2
Vector storePersistent Chroma collection named logistics_rag
Retrieval4 chunks per question
Language modelOllama llama3.2:3b, temperature 0, grounded prompt
Evaluation5 questions with reference answers, plus 1 question the files cannot answer
Answer similarityEmbedding cosine between the generated answer and the reference
Retrieval similarityHighest embedding cosine between the reference and the retrieved chunks
SourcesPrint the retrieved file names next to the answer
Answer similarity and retrieval similarity are similarity scores. They are not an accuracy percentage, and a high score is not proof the sentence is factually grounded. Wording can differ between machines. The grade looks at whether retrieval is relevant, the answer stays on the retrieved text, sources are traceable, and the write-up interprets the numbers.

How we are building it

The notebook runs locally from a Poetry virtualenv, Python 3.12, kernel Assignment05 (.venv). The same notebook is used on macOS and on Windows. Nothing in the notebook pins CUDA or Apple MPS. The embedding library and Ollama choose the device on the machine that runs the cell.

Packages are already in the virtualenv. The %pip cell is only a fallback for a machine that opened the notebook without that env.

Ollama has to be installed separately, then ollama pull llama3.2:3b, before any cell that generates an answer. Gemini is an optional API path in the brief. We are not using it, and no API key goes in the notebook.

Names the later cells will keep reusing: files, docs, then chunks, vectordb, and rag_chain.
