Four stages, one object

A chain here is a function from a question string to an answer string, with the retrieved documents available beside it. The imports already in the notebook are the pieces: a retriever, ChatPromptTemplate, init_chat_model, RunnablePassthrough, and StrOutputParser. You do not need a new framework.

  1. Retrieve. vectordb.as_retriever(search_kwargs={"k": 4}) returns four chunks. See Chroma.
  2. Format. Join those chunks into one context string. Include the file name in the string, or keep the documents alongside, so the printer can list sources. A join with a blank line between chunks is enough. A labelled block ("Source: SOP-COM-015...") makes the model's job and the reader's job the same job.
  3. Prompt. The prompt has the context and the question. The instruction has to say: answer from the context, and if the context does not contain the fact, say so. Without that sentence the model treats the chunks as a hint and fills the gaps from pretraining. That is the failure the unsupported-question test is designed to catch.
  4. Model. init_chat_model("llama3.2:3b", model_provider="ollama", temperature=0). The parser turns the message object into a string.

Temperature 0

Temperature scales the randomness of the next-token distribution. Zero asks for the most likely token at each step, greedily. The same question then tends to produce the same answer, which is what you want when you are about to score the answer against a reference. It does not make the model factual. A confidently wrong paraphrase at temperature 0 is still wrong. It does make a second run less likely to drift into a different wording and a different similarity score for no reason.

Ollama has to be running and llama3.2:3b has to be pulled before this cell. The Python package langchain-ollama only speaks to the local server. It does not download the weights. If the server is down, the cell fails. Do not swap in another model name to make the error go away. The brief names this one.

Llama 3.2 3B is a small model. On these policies it will miss nuance, collapse a table into a vague sentence, or copy a number from the wrong row if several rows were retrieved together. That is a limitation to write about in the conclusion, not a reason to change the spec.

Sources are part of the answer

The graded behaviour in section 2.2.2 is an answer plus the file names of the chunks that were retrieved. File names come from metadata, not from the model's prose. If you ask the model to "cite sources" and then trust the names it types, it can cite a file it was not shown. Print metadata["file_name"] from the four documents the retriever returned. Deduplicate them if two chunks share a file. The reader should be able to open those files and find the passage.

One question is enough for this section

The cell asks for a single logistics question as a smoke test, not the five-question eval set. Pick a fact you have seen in a file, for example a reporting window or a named role, so you can judge the smoke test by eye. The systematic set comes in section 3. If the smoke test names the right file and the sentence is in the right neighbourhood, the chain is wired. If it names a file from the wrong folder, fix retrieval or the prompt before writing five questions.
