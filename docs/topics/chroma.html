What we need from a database

After MiniLM encodes a chunk, we have a 384-float vector plus the text plus the metadata. A Python list of those triples would answer a toy query. It would also recompute every vector every time the notebook restarts, and the retrieval code would be a hand-written loop. Chroma is the small database that holds the triples and answers "which stored vectors are closest to this query vector?"

Closest, here, is cosine distance in the embedding space, because that is the distance we asked the embedding function to live in. You do not pass the TF-IDF matrix in. Different space, different index.

Collection, persistence, count

A collection is a named table of vectors inside Chroma. The brief names it logistics_rag. Use that string. A default name like "langchain" will run and will not match the brief.

Persistent means the vectors are written under a directory on disk, not only in the process. The next kernel restart can open the same collection instead of re-embedding. The directory is a cache. It is gitignored. Teammates rebuild it by running the cell. Do not commit the sqlite file.

The check after the load is the number of vectors. It must equal the number of chunks. A smaller count means a batch failed or the collection was opened from an older run and appended to. If you see double the chunk count, the cell added the same chunks twice. Delete the persist directory and run once, or open with a clean collection before adding.

What gets stored besides the vector

Chroma stores the document text and the metadata dictionary beside the vector. That is how a hit can return file_name without a second lookup. If metadata was dropped at chunking time, the vector search still "works" and the answer function has nothing to print. The failure shows up in section 2.2.2, not in the count.

Querying

A retriever with k=4 embeds the question with the same HuggingFaceEmbeddings object, asks the collection for four neighbours, and returns four Documents. Four is the brief. k=3 or k=5 changes the context the model sees and the retrieval-similarity score. Leave it at 4.

The first time this cell runs it will feel slow, because it encodes every chunk. On this corpus that is seconds to a minute, not a training job. If it appears hung, it is usually the model download or the first encode, not Chroma itself.
