What RAG is

Retrieval-augmented generation: find the passages first, then let the language model write from those passages only.

Two ways to answer, both wrong on their own

Ask Llama 3.2, with no documents, "what is AeroVelo's reporting window for a critical regulatory breach?" The model will produce a confident sentence. It has seen many policies in training. It has not seen SOP-COM-015. The number it prints might be two hours, or twenty-four, or something that sounds procedural and is not in the file. That failure is usually called hallucination. For this assignment the precise problem is narrower: the answer is not grounded in the folder we were given.

The other extreme is search without a model. Ctrl-F for "critical" inside one Markdown file works when you already know the file. It fails when the fact might be in any of ten files, when the question says "how fast must we escalate a criminal-liability incident" and the file says "Critical | 2 hours", and when the user wanted a sentence rather than a highlighted line. Keyword search also fails across the PDF extract, because the words on the page and the words in the question drift apart.

RAG is the combination. A retrieval step picks a few passages from the approved folder. A generation step writes the answer using those passages as the only allowed source. The notebook has to show which files the passages came from, so a person can open them.

The pieces, in the order we build them

  1. Corpus. Ten files under AeroVelo Logistics Global. See documents.
  2. Analysis, not retrieval yet. Lengths, word counts, and a TF-IDF cosine matrix tell us what the folder contains. They are graded, and they are not the index the assistant queries.
  3. Chunks. Whole policies are too big to hand to a model as "the" context for one question. We cut them. See chunking.
  4. Vectors. Each chunk becomes a MiniLM embedding so "escalate a breach" can land near "reporting window" without sharing those strings. See embeddings.
  5. Index. Chroma stores the vectors under the name logistics_rag. See Chroma.
  6. Chain. For a question, take the 4 nearest chunks, put them in a prompt that forbids outside knowledge, call llama3.2:3b at temperature 0, and print the source file names. See the RAG chain.
  7. Check. Five questions we can answer from the files, two similarity scores, and one question the files cannot answer. See evaluation.

What "grounded" has to mean here

A grounded answer is one a reader can trace to a retrieved passage. It is not an answer that happens to be true in the wider world. If the retrieved chunks do not contain the fact, the honest output is that the folder does not say. Inventing a plausible AeroVelo rule is a failure even when the prose is fluent.

The brief also says the notebook does not connect to live logistics systems. There is no database of shipments to query. The only knowledge base is the files in the dataset folder.

Temperature 0 and a small local model will still paraphrase. Evaluation therefore does not demand the reference sentence character for character. It measures whether the retrieved text was about the right thing, and whether the written answer sits near the reference in embedding space. Those scores are explained in the evaluation note. They are not a certificate that every clause is supported.

What we are deliberately not doing

  • No fine-tuning. The model stays llama3.2:3b as Ollama ships it.
  • No second vector space. TF-IDF is for the analysis section. Search uses MiniLM.
  • No device pin. The same notebook runs on a Mac and on a Windows machine.
  • No API key in the notebook. Gemini is an optional path in the brief. This project uses Ollama.
